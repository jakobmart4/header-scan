# Response-header catalogue (research input for PARITY-SPEC)

Scope: which response headers header-scan reports, how, and how loudly. Passive checks only. Tone: advisory findings are `warn`/`info`, never `fail`, unless there is a directly exploitable state (SPEC 2.4 / 3). Severity = SPEC weight (1-5) when the finding is W/F. Status letters: P pass, W warn, F fail, I info (not scored), S skipped.
`id` in **bold** = new check id proposed; plain `id` = existing id, only its rule is extended. Sources are numbered [n] in section 6; "(unverified)" = not confirmed by a fetch.

## 2. script-src hosts treated as CSP-bypass gadgets (seed list for `csp-script-bypass-hosts`)
Verified against Google csp-evaluator `allowlist_bypasses/json/jsonp.json` and `angular.json` [5] (fetched 2026-09-30). Match host-level sources only (exact host or `*.` pattern); ignore when `'strict-dynamic'` is present (it disables host allowlists [4c]).
- Google JSONP: `www.google.com` (whole host), `accounts.google.com`, `ajax.googleapis.com` (also hosts AngularJS), `*.googleapis.com` (maps, translate, mts*, storage), `*.googletagmanager.com` / `googletagmanager.com` (attacker-owned container runs arbitrary JS; needs an injection point, so W not F), `*.google-analytics.com`, `googleads.g.doubleclick.net`, `securepubads.g.doubleclick.net`, `pagead2.googlesyndication.com`, `translate.google.com`, `cse.google.com`, `www.gstatic.com` (AngularJS), `www.youtube.com`.
- AngularJS CDNs (sandbox-escape gadgets): `cdnjs.cloudflare.com`, `cdn.jsdelivr.net`, `oss.maxcdn.com`, `cdn.bootcss.com`, `cdn.shopify.com`, `ajax.googleapis.com`. `unpkg.com` is NOT in Google's list but serves any npm package incl. AngularJS: include (unverified, known technique).
- Shared user-content hosts (attacker can host a script): `*.cloudfront.net`, `*.amazonaws.com`, `*.appspot.com`, `*.herokuapp.com`, `*.github.io`, `raw.githubusercontent.com`, `*.blogspot.com`, `dl.dropboxusercontent.com`, `*.azureedge.net` (last one unverified).
- Not flagged: `js.stripe.com`, `static.cloudflareinsights.com`, `j.6sc.co`, the `https:`/`*` cases (already `csp-wildcard`). Expected on the fixture: `*.googletagmanager.com` W; `cdnjs.cloudflare.com` there is style-src only, so no hit.

## 3. Raw headers in the result JSON (item 6)
- Shape: `rawHeaders: [{name, value}]` in received order, lowercase names, max 100 entries, value truncated to 1024 chars (`...` + original length in `truncated`). Source: `page.headers`.
- `set-cookie`: one entry per cookie, value = `name=[redacted]; <attributes>` (keep Path, Domain, Expires, Max-Age, Secure, HttpOnly, SameSite, Partitioned; drop the cookie value entirely, even a short one). Never emit `Set-Cookie2`.
- Also mask the value (`[redacted]`) of headers whose name matches `/(token|secret|session|csrf|xsrf|api[-_]?key|auth(?!enticate$)|jwt|password)/i` and `proxy-authorization`, `authorization`; `www-authenticate` keeps the scheme word only (realm and nonce dropped). `location`/`link` are kept but query strings are stripped to `?[redacted]` when a query exists.
- Test: fixture cookie `anti_forgery_cookie=3ca967...` must not appear anywhere in the JSON; `expires=`/`Max-Age=7200` must.

| `hdr-legacy-headers` | headers.js | headers | 1 | P/W/I |
| `cors-wildcard-public` | headers.js | headers | 2 | P/W/I |
| `hdr-reporting` | headers.js | headers | 1 | I only (never scored) |
Existing ids with extended rules (no id/severity change): `hdr-coop`, `hdr-coep`, `hdr-corp`, `hdr-powered-by`, `hdr-server-leak` (Via), `hdr-permissions-policy`, `hdr-frame-protection` (evidence only).
Weight effect: +10 counted weight in `headers`, of which the fixture loses at most 2+3+2+2 = 9 (style, bypass, xss, cors) so A+ becomes a lower grade there; that is the intended superset behaviour (it still passes everything securityheaders.com checks). `hdr-reporting` and all COOP/COEP report-only cases are `info`, so they never reduce or inflate a score. A pass on `hdr-legacy-headers` is weight 1 only.
Tests: every new id needs a P and a non-P test; `hdr-reporting` is info-only, so test the two evidence variants (present/absent).

## 5. Deliberately not adopted
- Reporting X-Debug-Token(-Link), X-Runtime, X-Request-Id (not on MDN/OWASP lists I fetched; unverified framework knowledge).
- Grading `Timing-Allow-Origin`, `Clear-Site-Data`, `X-DNS-Prefetch-Control` (no exploitable state; raw table shows them).
- OWASP's maximal values (`COOP same-origin`, `COEP require-corp`, `CORP same-origin`, HSTS 63072000, `Referrer-Policy no-referrer`, `frame-ancestors 'none'`) are the recommended targets in fix text, not pass criteria: they break legitimate embeds, so pass criteria stay at "present and enforcing".
- Recommending HSTS preload as a default (hard to undo [3]).
